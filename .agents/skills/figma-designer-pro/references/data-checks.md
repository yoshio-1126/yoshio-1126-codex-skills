# Figmaデータの検査と編集

## 点検時の根拠
対象フレームと配下の実設定を読み、必要な場合に限り非表示レイヤーの設定も確認する。非表示は意図や状態が判明するまで温存する。以下は確認候補であり、自動的に指摘・修正する条件ではない。依頼範囲を超えて新しいデザイン要件を作らない。

- 整数指定がある箇所は対象の幅・高さ・余白・文字サイズ・線幅を照合する。浮動小数点由来の0.001 px未満の誤差と、縦横比を保つアイコン・写真の端数を切り分ける。
- 塗りの配列で重複する画像、マスク内の予期しない重複、参照されていない部品を調べる。同じ素材の再利用や異なる表示状態を重複ミスと数えない。部品はバリアント、プロパティ、参照元、意図した上書きを照合する。
- 案件で定義した変数・文字スタイル、行高と字間の単位、上下トリミングの扱いを実値と照合する。単色、画像、グラデーション、意図した直接指定を区別する。色変数を整理し、使われていない余白変数の作成を共通要件にしない。
- 納品対象、PC/SPの基準幅、可変幅の範囲、フォントのWeb利用条件、CMS・フォームの仕様は資料から確認する。未決事項は引き継ぎ用に区別し、デザイナーへの改善提言に変換しない。フォントのライセンスは利用条件を示す情報がなければ確定扱いにしない。
- 見た目だけで「誤り」と判定しない。直すと見た目や挙動が変わり、意図が分からない場合は対象を保つ。データを直す判断に必要な場合だけ、具体的な現象に絞って確認する。

## 許可された整理で使う基準
以下は整理作業の手順。点検時にルールとの差をそのまま指摘一覧にしない。

- 通常の並びはオートレイアウトのフローに含める。見出し帯やカードの境界線は、該当フレームの必要な辺だけにストロークを設定する。左右のアクセント帯も並びに入れ、本文の高さに追従させる。絶対配置は意図した重なり・はみ出し・追従ヘッダーなど、通常の並びから独立させる理由がある場合に限る。

- 横一列のボタン・ナビ・カード・写真は Horizontal、縦一列の項目・見出しと本文・セクション列は Vertical で組む。項目数が多くても、一列なら同じルールを使う。
- 行と列の両方をそろえる一覧（例：2列×3段）には Grid を使う。固定の列数が不要で幅に応じて折り返すタグ群には Horizontal の Wrap を使う。
- カードを横に並べる親は Horizontal、各カード内で写真・見出し・本文を積む親は Vertical とする。重ねる装飾は通常の並びから独立させる。
- 短いラベルは内容幅、段落は親幅に追従して高さ自動、等分のカードは親の空き幅を分ける。余白・項目間隔は親で管理する。
- 変換時は読み順、項目間隔、画像比率、インスタンス、プロトタイプのリンク先を保つ。長い文言・項目の追加削除で伸縮を試し、重なりや切れを確認する。
- カードの背景色と罫線は、本文を持つオートレイアウトフレームに設定する。模様や写真を別レイヤーにする場合は同じ親に入れ、カードの伸縮に追従させる。長文テストではカードの背景、次の行、CTAまで確認する。

- 余白は親の項目間隔と上下左右のパディングに設定する。間隔に差が必要なときは、見出しと本文など一緒に編集する実コンテンツをまとめる。本文からボタンまでの余白は、本文を高さ Hug にして、親の項目間隔で指定する。最小高はクリック領域やカード外形に下限が必要な場合、最大高はスクロール領域などに上限が必要な場合に使う。既存の高さ制約を外すときは、短文・長文の双方で見た目とボタン位置を確認する。幅や高さが1 pxの空フレームを余白用に挿入しない。

## 正本の置き場

- コンポーネントの正本は1つのFigmaセクションにまとめる。その中を配置時のサイズと用途に応じた通常フレームで整理する。ヘッダー・フッターなどページ幅で使う正本、カード、見出し、ボタン・リンク、ナビゲーション、アイコンなど、実際の部品数に応じてまとめる。使用見本は対応する正本の近くに置く。整理時は元の正本を移動し、インスタンスの参照を照合する。

## コンポーネントの用途メモ

- コンポーネントの新規作成・整理時は、正本の「説明」欄に、何をする部品か、どこで使うかを1〜2文で記載する。共通の用途はコンポーネントセットにまとめ、似た部品やバリアントがある場合は選ぶ基準も添える。整理時は既存メモを読み、用途が変わった箇所を更新する。
- 記載例（View More）：「枠付きはセクション末尾で主要な遷移先を示すときに使う。下線付きは一覧の各カードに詳細リンクを添えるときに使う。」

## 不要な透明レイヤーの整理

- 透明または非表示のレイヤーを見つけたら、操作領域、プロトタイプの遷移元・遷移先、マスク、コンポーネントの切替状態、オートレイアウトでの寸法への影響を確認する。表示・操作・編集のいずれにも役割がないレイヤーは削除する。削除後は周囲の寸法と配置を照合する。

## ページの導入と見出しの組み方

- FVと次の本文セクションは、それぞれ内容に応じた高さを持つ兄弟フレームとして、ページ本文の縦オートレイアウトに並べる。FVや次の見出しを絶対配置し、その高さを後続コンテンツの上パディングで確保する構造は避ける。追従ヘッダーのための上余白はFV内で管理する。
- 英字のあしらいと対応する和文見出しは同じ縦オートレイアウトに入れる。本文が続く場合は、この見出しの組と本文を外側の縦オートレイアウトに並べ、英字と和文の間隔と、見出しと本文の間隔を独立して編集できるようにする。既存の見出しインスタンスが適合する場合は再利用する。
- 整理後は、見出しの改行やFVの内容量を変えたときに本文と次のセクションが追従するかを確認する。

## 既存デザインの余白を引き継ぐとき

- 整理前に、番号・見出し・本文・画像・リンクなど、画面に見える要素同士の端から端までの間隔と並び順を控える。親の gap だけでなく、子の padding が作る実際の余白も含める。
- 同じ役割の箇所で1〜2 pxだけ異なり、視覚的なまとまりに影響しない場合は許容差とし、その差だけを理由に入れ子を増やさない。意図が明確な差は小さくても維持する。
- 差が2 pxを超える場合や、番号と見出し、本文とCTAなど役割の切れ目で間隔が変わる場合は、元値を維持する。関連する実要素だけを最小限の Auto Layout にまとめ、内側と外側の gap、必要な padding で再現する。固定幅・固定高の空フレームを余白代わりにしない。
- デザイン意図が読み取れず、統一すると見た目が変わる場合は、元値を維持したまま対象箇所と数値を示してユーザーに確認する。変更後は、編集前と同じ可視要素間を再測定する。

## 内容にフィットする枠と見切れの検証

- まず親幅の決まり方を選ぶ。幅が決まった子を並べ、その合計に外枠を合わせるなら横方向を Hug contents とする。使える横幅が先に決まるカラムでは、行と等分する子を Fill container にし、折り返す本文は高さ自動にする。縦組みでは高さについて同じ判断をする。
- 横並びの必要幅は、左右のパディング＋各項目の幅の合計＋間隔×（項目数−1）。罫線をレイアウトに含めたときはその実寸も確認する。例えば280 pxの列3本と20 pxの間隔2つには880 pxが必要で、860 pxの固定幅では右端20 pxが枠外に出る。
- 子テキストが直接の親に収まっても、途中の行やカードが小さければ表示は切れる。全ての可視テキストについて、行・カード・セクションを遡り、クリップする各祖先の内側に上下左右とも収まるかを実寸で確認する。右端の列と最終行を実画像でも見る。クリップ解除だけで済ませず、幅や高さを決める親・子の設定を直す。
- 本文と強調値を長くした場合、項目間隔を変えた場合を複製で試す。祖先での切れ、後続要素との重なり、外枠の追従を検証し、検証用コピーを片付ける。

## 子の寸法を変えたときの親への追従

- 列や部品の寸法を編集する設計では、どの子が幅を決め、どの祖先まで追従し、どこでページ幅・一覧幅に戻るかを先に定める。内容で幅を決める列の親と中間ラッパーは横方向 Hug contents にする。右寄せのリンク行には、説明エリアの幅が確定した後で Fill container を使う。
- 複製で1列だけを40 px狭め、編集した列、列の行、中間ラッパー、カード外枠、リンクの右端を前後で測る。追従が途中で止まれば、その祖先の Fixed、Fill、最小幅、または幅を決めている別の兄弟を確認する。意図して全幅の一覧は追従の終点として扱う。
- 高さも Hug contents の表示だけで判断しない。子の実寸・パディングから必要高を求め、minHeight、他の列の高さ、親の高さ揃えと比較する。最小高を外すとカードやCTAの位置が変わる場合は、等高を意図した設定かを確認する。見た目を維持して内容にフィットさせる場合、必要な間隔は隣り合う要素の親の gap で表し、複製で両方を実測する。
