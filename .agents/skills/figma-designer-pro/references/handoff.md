# 引き継ぎ成果物

## 作る前に
現行版・退避版・参考素材・確定範囲を特定し、既存資料のリンクをたどる。納品するPC/SPはページ名・対応画面が明瞭になるよう整理する。修正中の別案や比較用の複製を納品版に混ぜない。過去データの一括削除は行わない。

## デザイナー用
正本をまとめた1セクション内の各部品に短い用途メモを付ける。案件ごとに1枚の白地の仕様表を作る。左セルは設定項目、正本につながる実物インスタンス、適用済み文字スタイル、色変数の見本。文字見本はダミーと分かる例文にし、Web画面の切り抜きを貼らない。右セルは設定値・単位・用途とし、資料用の背景を標準 #ECECEC にして行高全体を塗る。説明色はプロジェクトの色定義に追加しない。独立した未記入版を増やさない。表を実際に表示し、説明の折返しや参照切れを確認する。

## コーダー用
案件仕様書の先頭に「実装引き継ぎ」を用意し、そこから必要な情報に到達できるようにする。納品要件で必要なら独立した指示書にして相互リンクする。以下から該当するものだけを記載する。

- 現行の対象画面、PC/SPの対応フレーム、正本と素材の場所。
- 確定した幅・余白・ブレークポイント、幅と高さが Fixed / Hug / Fill のどれか、可変幅での折返し、画像比率・トリミング。PC/SPの2枚だけを根拠に中間幅の挙動を推定しない。
- 共通コンポーネント、バリアント、色・書体、文言や画像の差し替え、意図した例外。共通値・正本の実値・インスタンスの上書きを明記して区別する。
- 対象に含まれる場合は、CMSの入力制約、最大件数・長文・空状態、フォームの必須・任意・エラー、既に決まっている開閉・表示状態。挙動は支給仕様または既存プロトタイプで確定している事実だけを転記する。画面の導線は設計・評価しない。
- 未決／未確認の事項と、チームで既に決まっている確認先。SPの実機確認は実施した端末・条件がわかるときだけ確認済みにする。

## 次のチャット用
案件目的と対象、合意事項、例外、根拠ノード、最新の検査範囲、実装に関係する未決事項をFigmaファイル内の案件仕様書に保存する。環境で利用可能な文書機能を先に確認する。書き込めないときは取得できた事実を引き継げる文書で渡し、保存先・未反映範囲を伝える。既存の文書やコメントを保ち、更新を重ねても入口を分散させない。機密素材や個別案件の数値を配布用スキルに含めない。

提出前に「今回の納品対象はどれか」「本文サイズと例外は何か」「この画面のSP・CMS条件は確定しているか」を仕様書と実ファイルで照合する。次のチャットで仕様を尋ねられたら、案件のFigmaリンクから現行文書・対象ノードを読み、単位・適用範囲・根拠リンクとともに短く返す。
