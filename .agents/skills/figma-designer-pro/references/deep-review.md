# 詳細点検の手順

## 読み取りと照合

各対象を一度走査して候補を集め、次に候補の親と正本を詳しく調べる。大きいファイルはページ→トップレベルフレーム→下位の枝に分割する。実画面、正本、参照先ライブラリのうち読めた範囲を区別する。点検中の控えにはページ・ノードID、該当状態、実値、参照元、確認手段を残す。読み取り依頼では控えをFigmaに書き込まない。

| 見るところ | 確かめ方 | 誤検知を避ける条件 |
| --- | --- | --- |
| 本文、親のサイズ追従 | テキストの自動調整・折返し・行高・行数上限から親を順に辿り、必要な領域とクリップする祖先の境界を比較。実際の表示でも最終行を確認する | 固定幅の本文でも、高さが伸びて全文が見えれば見切れとは扱わない。スクロール領域・意図した省略も除く |
| 背景、罫線、見出し | ボックスと本文が同じ親で伸縮するか、英字と和文の並びが同じ見出しに属するか、絶対配置が他の内容に重なるかを調べる | 写真上の装飾や固定ヘッダーには重なりの用途がある。ノードの矩形だけで断定しない |
| 余白と可変幅 | 軸ごとにHug・Fill・Fixedとmin/maxを祖先まで辿る。gapとpaddingを含めて必要寸法を算出し、グリッドは列・行・スパンごとに確認する | 等高カード、意図した余白差、画像比率、折返しを考慮する。整理で同種の間隔に1〜2 px差があるだけなら許容。大きい差は元値と用途を保つ |
| 正本とインスタンス | 同じ役割の実使用ノードを正本ID・プロパティ・上書き・参照先で照合する。正本由来か、その画面だけの差かを分ける | 表示名や外見の一致だけで統合しない。外部正本を読めない場合は所在・影響を推測しない |
| 文字・色・変数 | 混在テキストは範囲別に書体・スタイルを読む。変数の別名参照と対象フレームのモードで実効値を照合する。案件に明示された割当と比較する | 同じRGBでも役割の異なる変数はあり得る。現行制作画面の未スタイル・行間の％指定漏れを範囲別に点検する |
| 透明・非表示・空の層 | 寸法、子、クリップやマスク、部品プロパティとの結び付き、既存操作、余白や当たり判定の役割を調べる | 表示切替・当たり判定・スロットには意味がある。不要と確定できた場合のみ整理対象とする |

## 文量・状態の確認

読み取り時は、既に存在する最長・最短の本文、狭い幅の実画面、補足あり／なしなどを選ぶ。同じ正本で比較できる実例を優先する。存在しない状態は、現在の文面の確認と分ける。数式や境界で説明できても、文言を実際に差し替えたと表現しない。

複製での検証も依頼されたとき、または整理の動作確認として許可範囲に含まれるときは、コピー上で一項目ずつ変える。案件の長文、親幅、補足の表示切替、グリッドの一件追加など、変更の影響に合うものを選ぶ。前後の高さ・後続要素の位置・最寄りのクリップ境界を取得し、実際の表示を確かめる。失敗時も自分が作った検証コピーだけを片付ける。元の正本をテストに使わない。

## 判定例

- 見出しの下端が親から出ていてもクリップが無効で重なりもない場合、座標だけで「見切れ」としない。実際に文字が隠れた場合は、どの親が隠すかまで特定する。
- 補足を隠したカードに空きがある場合、等高仕様か、空のラッパーがgapを残しているかを調べる。確認できた原因と範囲を報告する。
- 同じ名前のボタンが二つある場合、用途、バリアント、参照先を比較する。明示された正本とは別の複製を実画面が参照し、対象の更新が届いていないと確認できたら、その画面と正本を示す。
