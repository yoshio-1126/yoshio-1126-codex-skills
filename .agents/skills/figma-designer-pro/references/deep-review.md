# 詳細点検の手順

## 読み取りと照合

各対象を一度走査して候補を集め、次に候補の親と正本を詳しく調べる。大きいファイルはページ→トップレベルフレーム→下位の枝に分割する。実画面、正本、参照先ライブラリのうち読めた範囲を区別する。点検中の控えにはページ・ノードID、該当状態、実値、参照元、確認手段を残す。読み取り依頼では控えをFigmaに書き込まない。

| 見るところ | 確かめ方 | 誤検知を避ける条件 |
| --- | --- | --- |
| 本文、親のサイズ追従 | テキストの自動調整・折返し・行高・行数上限から親を順に辿り、必要な領域とクリップする祖先の境界を比較。実際の表示でも最終行を確認する | 固定幅の本文でも、高さが伸びて全文が見えれば見切れとは扱わない。スクロール領域・意図した省略も除く |
| 背景、罫線、見出し | ボックスと本文が同じ親で伸縮するか、英字と和文の並びが同じ見出しに属するか、絶対配置が他の内容に重なるかを調べる | 写真上の装飾や固定ヘッダーには重なりの用途がある。ノードの矩形だけで断定しない |
| 余白と可変幅 | 軸ごとにHug・Fill・Fixedとmin/maxを祖先まで辿る。gapとpaddingを含めて必要寸法を算出し、グリッドは列・行・スパンごとに確認する | 等高カード、意図した余白差、画像比率、折返しを考慮する。同種の間隔が1〜2 px違う場合も比較し、正本・同型要素と原因を確かめる。大きい差はカード全体の上下・左右を同じ基準で測り、揃える意図をデザイナーに確認する |
| 正本とインスタンス | 同じ役割の実使用ノードを正本ID・プロパティ・上書き・参照先で照合する。正本由来か、その画面だけの差かを分ける | 表示名や外見の一致だけで統合しない。外部正本を読めない場合は所在・影響を推測しない |
| 文字・色・変数 | 混在テキストは範囲別に書体・スタイルを読む。変数の別名参照と対象フレームのモードで実効値を照合する。案件に明示された割当と比較する | 同じRGBでも役割の異なる変数はあり得る。現行制作画面の未スタイル・行間の％指定漏れを範囲別に点検する |
| 透明・非表示・空の層 | 寸法、子、クリップやマスク、部品プロパティとの結び付き、既存操作、余白や当たり判定の役割を調べる | 表示切替・当たり判定・スロットには意味がある。不要と確定できた場合のみ整理対象とする |

## 文量・状態の確認

読み取り時は、既に存在する最長・最短の本文、狭い幅の実画面、補足あり／なしなどを選ぶ。同じ正本で比較できる実例を優先する。存在しない状態は、現在の文面の確認と分ける。数式や境界で説明できても、文言を実際に差し替えたと表現しない。

複製での検証も依頼されたとき、または整理の動作確認として許可範囲に含まれるときは、コピー上で一項目ずつ変える。案件の長文、親幅、補足の表示切替、グリッドの一件追加など、変更の影響に合うものを選ぶ。前後の高さ・後続要素の位置・最寄りのクリップ境界を取得し、実際の表示を確かめる。失敗時も自分が作った検証コピーだけを片付ける。元の正本をテストに使わない。

## 整理後の編集操作の試験

編集が許可された範囲の一時コピーで、異なる構造ごとに代表例を選ぶ。この代表試験は編集操作が対象。見た目の比較は共有正本でも全使用先を実測する。親構造や上書きが異なれば別に試す。

- Web画面では、整理後のセクションの主要な子をレイヤーパネルまたはノードツリーでたどる。見出しが受け持つ内容を読み順に取り出せるか、本文側を一度選ぶと概要から最後の下位項目まで含まれるかを、想定した意味構造と照合する。全体見出しが先頭行にだけ入り、後続行が同じ左余白を個別に持つ構造なら、列の親を見直す。
- 横並びの見出し・本文は、一時コピーで最も幅を取る見出しを短くし、次に長くする。各時点で見出しの外枠幅、右列の開始位置、実要素間のgapを比べる。文字だけが伸縮して、外枠に余白や越境が生じたら中間枠まで直す。元の文言で開始位置と見える間隔が元通りかも照合する。
- 高さが変わる段落では実際に改行を増やし、元の余白、リンクや隣接要素の位置、外枠と次のセクションの位置を前後で比べる。他の列や最小高が高さを決める場合は、その高さを超える文量でも試す。
- 繰り返し項目では一件を並べ替えるか増減する。付随する画像・番号・ラベルが一緒に動き、周囲の順序と間隔が保たれることを確かめる。共通部品は正本の参照先と意図した上書きの維持も照合する。
- コンポーネントでは、作業用正本の行・列を内側まで読み返し、通常要素が各親のフローに入っていることを確かめる。ヘッダーではナビの文言を伸ばして隣接項目の間隔と端の整列を、フッターでは住所を長くしたりリンクを追加したりして電話番号・後続の区画・関連する縦罫線の追従を測る。幅に追従する設計では、その部品を使う画面をリサイズし、内部の列や写真枠まで幅が変わることを確かめる。
- 現文言に戻した基準幅の表示を整理前の記録と比べる。全体の縮小画像に加え、改行・字詰め・トリミングなど変化しやすい箇所は等倍の領域または実測値を使う。表示の一致と編集操作の合否は個別に記録する。

## 修正後の枠と間隔の照合

- **新しく作った枠も調べる。** 最終状態の制作フレームに[親子境界の検査](../scripts/content-fit.js)を再実行する。部分修正なら変更した枝・その親・影響先を対象とする。結果は文字に絞らず、本文や図を包む行・列・カード・インスタンスまで照合する。親の実寸、内側の余白、子の開始位置と外寸から、どの辺を何 px越えたかを求める。折り返しや文字切れがなくても、通常の配置枠が出ていれば記録する。絶対配置の意味のある内容は個別に確認し、意図した装飾や図版内部のパス、変形の演算誤差とは区別する。
- **同じ役割の要素をもう一度測る。** 変更した繰り返し項目とその比較相手を、同じ基準幅・状態で全件並べる。図の下端からラベルの上端、番号の右端から見出しの左端など、役割に合う二辺の実寸を同じ座標系で引き算する。親の gap が同じでも、内側の余白や個別の位置指定で目に見える間隔は変わる。並べ替え試験に合格した項目も測る。
- **承認内容と結果を突き合わせる。** 承認した寸法、または比較対象の実測を基準に、既存の差・修正で生じた差・意図して維持した差を区別する。承認範囲の不具合は直して再計測する。意図の判断が要る差は現在の値を保ち、修正版の該当箇所に注釈として、デザイナーが決める見た目の違いを短く残す。構造や試験値は検証記録に控える。読み取り専用のレビューではチャットに報告する。

## 判定例

- 見出しの下端が親から出ていてもクリップが無効で重なりもない場合、座標だけで「見切れ」としない。実際に文字が隠れた場合は、どの親が隠すかまで特定する。
- 補足を隠したカードに空きがある場合、等高仕様か、空のラッパーがgapを残しているかを調べる。確認できた原因と範囲を報告する。
- 同じ名前のボタンが二つある場合、用途、バリアント、参照先を比較する。明示された正本とは別の複製を実画面が参照し、対象の更新が届いていないと確認できたら、その画面と正本を示す。
