# 整理時の指摘セクション

## 指摘の優先順

まず見た目から編集単位を拾う。元のレイヤーにカード枠や名前がなくても、同じ役割の写真・見出し・本文の組を横断して調べる。セクションやカード全体に及ぶ指摘を先に、孤立した細部の差は後に置く。

- **文字スタイル**　初回のチャットと、作成する場合は指摘セクションに、実使用種類数・個別書式の層数と、同じ変更を一緒に反映したい見出し・本文の実例を載せる。分けておくものは、独立して変更したい理由を添える。
- **内容と固定枠**　列の外枠と内側の行をそれぞれ見て、どの親で幅・高さの追従が止まるかを示す。複製に親の端と子の端を示し、現状の越境量、内容幅にする箇所、列位置を保つ箇所を伝える。
- **文字枠だけがはみ出す箇所**　複製に親と文字枠の端を表示し、「文字は収まる／文字枠は右に○ px」など、方向と量を添える。表示上の見切れと区別し、文言変更・整列・次の要素の配置に関わる理由をひと言添える。大きな構造の指摘を優先する場合も、同じセクション内の一覧から小さな差を確認できるようにする。
- **同型カードの余白**　同じ基準辺から本文ブロックの先頭・末尾までの距離、カード同士の間隔を全件で並べる。カード枠がない場合は行を定義する写真や背景の上下端を基準にし、何を測ったかを明記する。文量や高さが違うときは、中央揃え・上揃えなど一つのルールで説明できるかを見る。説明できないばらつきは、上下の実測と推奨する揃え方を比較して示す。
- **写真と本文の関係**　画像の実体、画像枠、本文、正本の親子関係をたどる。写真がカード外に浮く、画像枠の上を別画像で覆う、絶対配置でカードらしく見せている場合は、写真差し替え・カード幅変更で何が起こり得るかを示す。通常の横組・縦組や既存のサムネイル枠で表せるならその構造を提案する。意図した重なりや図版の内部は別に扱う。
- **セクション間の共通リンク・ボタン**　同じ役割のリンク・ボタンを指定画面全体から拾う。正本が違うものや手組みのものも含め、各使用箇所のセクション名とノードIDを控える。外側は同じ列・揃え方のもの同士で、列の基準辺から対応する端までを測る。内側は文字とアイコンの上端差・間隔を、それぞれの外枠から独立して比べる。色や置き場所が異なる場合も、比較できる寸法だけを見る。基準幅・比較対象・差の方向を記録し、1 pxでも差があれば該当箇所と提案を指摘に載せる。意図した別状態は根拠を添える。
- **小さなズレ**　同じ基準線から測り、1 pxなど目視しづらい差には、複製に共通のガイドを引く。構造の指摘を先頭に置き、同じカードの中で独立して判断できる差はその後にも残す。繰り返しごとの実測値と対象名、変更量が分かるようにする。原稿の仮置きや画像枠とのずれも実物で確認する。
- **小数の内訳**　初回の検査では対象フレームを母数に、配置や外枠に生じた端数をレイヤー数と設定値の数で示す。UI表示で整数に見える精度差も生値を残す。図版内部の輪郭・回転や、線のない要素に残る線幅など、表示への働きが異なる値は別集計する。同じレイヤーでもプロパティ単位で判定する。親の中央揃えで生じた半端な位置は親子の寸法と合わせて説明し、承認後の修正案を示す。
- 繰り返す要素の役割・子の構造・上書き・正本参照を調べる。共通化すると何を一括更新でき、どの文言や画像を個別に変えられるかまで示す。外見だけ似た異なる部品は分けて扱う。
- まとまり・読み順・長文時の追従も同じ観点で調べる。根拠が弱い箇所は「要確認」とし、実測と推測を分ける。件数合わせの指摘を作らない。

## Figmaへの残し方

- 制作画面の外に「指摘｜対象名」というFigmaのセクションを置く。元画面とバックアップから離し、重なりや画面への写り込みがないことを確認する。同じ対象の指摘セクションがあれば既存コメント・判断履歴を保って更新する。
- 番号付きで、現状の該当ノードをネイティブ複製し、比較できる周辺・同型要素も必要な範囲で含める。縮尺を変える場合は測定値の基準を記す。問題箇所を囲みや矢印で示し、その横に「観測値と比較対象」「修正案と影響」「反映済み／承認待ち／要確認」を短く書く。比較案が有効なら、別の複製にのみ適用して元と並べる。複製は正本へ変更を波及させない。各項目から制作画面の該当箇所が特定できるようにする。
- 「要確認｜このカードだけ左余白が25 pxで、同型2枚は24 pxです。24 pxにそろえますか」「改善案｜この3行は見出しだけが違います。1つの正本にするとアイコンの変更を3行に反映できます」のように具体化する。指摘がなければ、空のセクションを追加せず検査した範囲と結果を伝える。
- 見た目が変わる案は、指摘の中で「デザイン変更案」と分かるようにし、基準にした実物と変更する箇所、見た目に出る差を示す。例えば「同じカード4枚のうち1枚だけ見出し下が24 pxで、ほかの3枚は16 pxです。4枚とも同じ役割なので、16 pxにそろえる案をおすすめします。このカードの本文が8 px上がります。①そろえる ②今の余白を残す」。整理を任された場合は指摘用の複製に現状と案を並べる。読み取り点検ではチャットに返す。
- 測定の詳細はFigmaに残す。チャットでは、見た目が変わる全件を承認一覧に載せ、対象・指摘へのリンク（反映後はバックアップも）を返す。未決の仕様や不足ページ候補など本人の判断が要るものだけをまとめて質問する。不足ページはサイトマップ等の根拠と照合し、範囲外や未制作の可能性があれば「不足の候補」とする。承認待ちには、「選んでいただいた項目を作業コピーに反映します」と添える。

## 文字と色の集約リスト

初回の承認一覧を読めば、どの箇所をどの基準へ寄せるか、件数と見た目の影響が分かるようにする。役割が共通なら元の値が完全一致しなくても候補に入れる。見出し・本文・注記について文字サイズ・ウェイト・行間などの現状と推奨値を並べる。同じ目的の本文に複数の行間があるなら、適切な代表値に寄せた場合にどの段落の高さや余白が変わるかまで示す。色は役割・現状の色見本・推奨色・適用先を対にする。見送りや別管理の理由も短く添える。

- **集計の物差し**　対象と採用する設定項目を固定する。文字は実効書式の組み合わせ数と参照する共有スタイルID数を別欄に、色は対象に実使用の単色RGBA数と参照定義数を別欄にする。未スタイルの原稿も元の書式を数えれば比較できる。個別で残す文字・図版色などの対象数と除外範囲を示す。候補同士の重複を除いて全案採用時の合計を計算する。
- **残すもの**　文字見本・色チップとともに「番号／対象と用途／現状の種類数と値／採用後の種類数と値／どこがどう変わるか／個別に残すもの／状態」を見比べられる一覧を置く。背景装飾は対象と通常フレームにする範囲を同じ承認一覧に載せる。読み取り点検ではチャットとローカルの表で提示する。整理を承認されたら制作画面の外のFigmaセクションに比較リストを残し、提案値の隣に完了後の実測値を記してチャットからリンクする。比較用の文字や色見本は制作画面の実使用数に含めない。
