# Figmaの制作データを整える

指定された実データ、関連する親・正本、案件で合意した仕様を根拠にする。ファイル指定なら現行の制作ページを特定し、保管・検証用の複製は集計から外す。対象を取得できず別候補で結果が変わるときは確認する。新規制作では次に差し替える文章・画像を含む代表画面を起点にする。Webの品質監査、不足ページの判定、サイトマップ作成、要件ヒアリングは別の仕事として扱う。

## 初回の点検と返答

指定範囲で次の三点を確認する。報告の短さを理由に、検査や独立した指摘を省かない。

- **構造・表示**　一緒に動かす写真と説明の親子関係、文章が増えたときの枠の追従、文字のはみ出し、部品の参照先を実物で確かめる。枠だけが出ている場合は、その状態を正確に書く。
- **配置の小数**　基準幅で[整数寸法の検査](references/data-checks.md#整数寸法の全件検査)を行う。配置枠の座標・幅・高さ・間隔の端数は、表示が崩れていなくても対象。中央揃えなど親子の寸法から生じた場合はその原因を押さえ、図版の輪郭・回転・計算誤差は除く。
- **同じルールからのずれ**　同じ役割・状態の項目を全件、同じ辺から測る。間隔・整列・文字設定などが正本や共通列から外れていれば、該当箇所と比較値を示す。意図した強調や図版内の目合わせは保つ。数値が近いだけで統合しない。

一任された整理への初回返答は「現状、次の問題があります。」に続け、確認できた問題を一項目一行で列挙する。同じ原因の反復は対象と件数でまとめ、原因の異なる不備は残す。修正方法・検査手順・選択肢は並べず、最後は「これらを修正しますか？」の一問で終える。問題がなければ一文で終了。点検・報告のみの依頼では修正を尋ねない。

承認は列挙した不備の修正に適用する。具体的な修正指示は再確認せず進める。見た目の意図や指定外の影響先が決められない箇所だけは、反映前に確認する。

## 制作・反映・引き継ぎ

承認後は対象と変更するローカル正本の編集前バックアップを取り、別ID・親・寸法・表示・参照を読み戻す。通常は別の作業コピーに反映する。共有正本・スタイルの変更が原本やバックアップへ波及する場合は参照を独立させ、復元できない枝は保留する。原本への直接反映には反映先の明示が必要。

文章や画像は一緒に選ぶ単位でまとめ、通常の並びは親の間隔で調整し、図版の自由配置を保つ。対象に応じて[構造・文字・色の基準](references/data-checks.md)の該当節を使う。[編集操作の試験](references/deep-review.md#整理後の編集操作の試験)で、文量変更・並べ替え・一括更新など提案した操作を作業用の複製で確かめる。試験後は実際の結果を再取得し、承認した表示差、越境・間隔・小数、正本と上書きを照合する。修正・検証を終えたら、[Figmaに残すビフォー・アフター](references/feedback.md)を作り、チャットには完了の一文と実例へのリンクを返す。利用に関わる残件だけを添え、バックアップや測定の詳細は引き継ぎに置く。

納品・他担当への引き継ぎを頼まれた場合は[引き継ぎ資料](references/handoff.md)を使う。
